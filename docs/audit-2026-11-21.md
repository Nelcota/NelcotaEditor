# Auditoria técnica e proposta de arquitetura (2026-11-21)

Escopo: todo o `src/` (353 arquivos, ~24 mil linhas), o worker, o `docker-compose.yml` e o histórico do git.
Cinco frentes independentes, cada achado conferido no código antes de entrar aqui:
correção numérica e nulos; segurança, bots e módulos; concorrência, performance e escala;
erros, logs, testes e SOLID; hierarquia visual de todas as telas.

Fila de PRs: vazia. O único PR do repositório (#2) já foi revisado, corrigido e mergeado.

## Resumo

O código está em bom estado nos pontos clássicos: nenhuma injeção de SQL ou de comando, nenhum path
traversal, nenhum XSS, autorização por dono em todas as 22 server functions e rotas `/api`, Zod em todas
as bordas, divisões protegidas contra zero, nenhum segredo no histórico. Os riscos reais estão em
**abuso** (nada limitava trabalho caro por usuário), **concorrência** (transições de status sem
condição no SQL), **escala** (um worker, um vídeo por vez, disco local) e **acoplamento entre módulos**
(`videos` tem 52% do código e dependências nos dois sentidos com quase todos os módulos).

## 1. Arquitetura atual

Monolito modular em TanStack Start (React 19 + Nitro), Postgres com Drizzle, fila pg-boss no mesmo
Postgres, um worker Node em Docker que roda yt-dlp, ffmpeg, Whisper (speaches, CPU) e DeepSeek.
Arquivos em disco local (`./storage`), compartilhado entre web e worker por bind mount.

| Área                                                       | Linhas | Arquivos |
| ---------------------------------------------------------- | ------ | -------- |
| `modules/videos`                                           | 12.425 | 159      |
| `shared`                                                   | 3.579  | 65       |
| `modules/auth`                                             | 2.733  | 40       |
| `modules/overview`                                         | 1.603  | 27       |
| `modules/clips`                                            | 1.116  | 12       |
| `highlights`, `processing`, `transcription`, `preferences` | 1.750  | 27       |

Dependências entre módulos que vão nos dois sentidos (deveriam ser de mão única):
`videos ↔ clips` (45 / 2 imports), `videos ↔ auth` (10 / 6), `videos ↔ processing`,
`videos ↔ transcription`, `videos ↔ highlights`, `clips ↔ highlights`, `processing ↔ transcription`,
`highlights ↔ transcription`. Não há ciclo entre arquivos, só entre módulos.

## 2. Proposta de arquitetura

Princípio: manter o monolito modular (é a escolha certa para o tamanho do time e do produto), mas
torná-lo **de verdade modular** e preparar os três pontos que não escalam. Nada de microserviços.

### 2.1 Limites de módulo com direção única

```
routes ──► modules ──► shared
              │
   auth ◄─ library(videos) ◄─ studio(clips) ◄─ overview
              ▲
   pipeline: processing ─► transcription ─► highlights ─► rendering
```

1. **Dividir `videos`** (o "módulo deus"):
    - `library`: vídeos, lista, upload, link do YouTube, status, exclusão.
    - `studio`: tudo de `videos/ui/studio/**`, `clip-studio-*`, `clip-edit-functions` (hoje 28+ arquivos
      de cortes morando em `videos`).
    - `clips` passa a ser dono de cortes, render e compartilhamento.
2. **Contratos públicos por módulo**: cada módulo expõe um `index.ts` (tipos e funções públicas). Outro
   módulo só importa dali. Regra no `oxlint` (`no-restricted-imports`) proibindo `#/modules/x/server/*`
   e `#/modules/x/ui/*` fora do próprio módulo. Isso pega o acoplamento no CI, não na revisão.
3. **Constantes de domínio no dono**: `MAX_CAPTION_WORD_LENGTH` sai do schema do Studio para
   `transcription`; `toOverallPercent` vai para `processing` e é só lido por `library`;
   `CLIP_VIEW_COLUMNS` deixa de ser importado pelo `overview` (expor `listClipsForOverview()`).
4. **Pipeline como estágios explícitos** (sem framework novo): cada estágio (`download`, `transcribe`,
   `select`, `render`) é uma função `ensureX(videoId)` idempotente que já existe; formalizar a máquina de
   estados do vídeo num único mapa de transições permitidas (`ALLOWED_PREVIOUS_STATUSES`) aplicado no
   `WHERE` de todo `UPDATE` de status.

### 2.2 Escala (próximos passos, em ordem de custo)

| Gargalo hoje                                        | Quebra em                        | Passo barato                                                                                                             | Passo seguinte                                                                                |
| --------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Worker com `localConcurrency: 1`, fila global FIFO  | ~10 usuários ativos              | `work(..., { localConcurrency: 2, groupConcurrency: 1 })` + `send(..., { group: { id: userId } })` (justiça por usuário) | Mais réplicas do worker, com `heartbeatSeconds` no lugar do "falhar todos os ativos ao subir" |
| Worker assume réplica única (`releaseOrphanedJobs`) | 2ª réplica ou restart sobreposto | `pg_try_advisory_lock(hashtext(videoId))` em `processVideo`                                                              | Índice `UNIQUE(clips.video_id, position)` para impedir cortes duplicados                      |
| Disco local compartilhado                           | 2º host                          | Gravar `source_bytes`/`output_bytes` no banco (acaba a varredura de disco por request)                                   | Object storage (S3/R2) com URLs pré-assinadas; os caminhos já são relativos                   |
| Whisper CPU único                                   | vazão de transcrição             | Dimensionar `localConcurrency` pelo nº de workers do speaches                                                            | Whisper em GPU ou API                                                                         |
| Polling de 2,5 s da lista inteira                   | muitos vídeos/abas               | Endpoint leve só com vídeos em andamento; paginar a lista                                                                | Eventos (SSE) a partir do worker                                                              |

### 2.3 Plataforma

- **Testes**: Vitest (já usa o `vite.config.ts` e o alias `#/`), `*.test.ts` ao lado do arquivo. Antes,
  tirar a lógica pura de arquivos `.server.ts` que importam `db` (o `database.server.ts` lê o env ao ser
  importado e quebra qualquer teste). Lista de casos na seção 6.
- **Observabilidade**: logs estruturados (`{ videoId, jobId, stage, ms }`), um wrapper de erro para as
  rotas `api/*` (hoje fora do middleware que esconde erros internos).
- **Segurança operacional**: rate limit do Better Auth ligado com `storage: "database"` e
  `trustedProxies` do proxy real; Turnstile no cadastro; verificação de e-mail.
- **Colunas de tempo**: `timestamp with time zone` em todas as colunas (hoje mistura `defaultNow()` do
  Postgres com `Date` do JS; só funciona porque o container está em UTC).

## 6. Erros, logs, testes e SOLID

- **Erros que a pessoa vê**: falhas do ffprobe e do Whisper viravam "Algo deu errado". Corrigido com
  mensagens que dizem o que fazer.
- **Logs**: início e fim de job com `videoId`, `jobId` e duração; `videoId` nas falhas de corte. Corrigido.
- **Pendentes**: `recordStop` sem `try/catch` (vídeo preso se o banco cair na hora de marcar a falha);
  insert + enqueue não atômicos (vídeo duplicado em retry); rotas `api/*` sem wrapper de erro.
- **Duplicação**: `findTranscriptWords` duas vezes com contratos diferentes; teste de ENOENT em 4
  arquivos; `removeVideoDirectory` existe mas é reimplementado em 4 lugares; `errorResponse` e
  constantes HTTP copiadas em 7 arquivos. Proposta: `shared/server/http-response.ts` e
  `shared/server/fs-errors.ts`.
- **Primeiros testes e casos de borda**:
    1. `normalize-highlights`: sobreposição de 0,9 s (aceita) e 1,1 s (recusa), fim antes do início,
       vídeo menor que 15 s, corte encostado em 90 s com padding, `durationSeconds` NaN/0, transcrição vazia.
    2. `clip-studio.schema`: 15,00 s e 90,00 s com erro de float, 14,99 s e 90,01 s, legendas que se tocam

## 7. Corrigido nesta rodada

Servidor e segurança:

- Transições de status atômicas: reenfileirar só vídeo terminado; estágio não sobrescreve cancelado;
  cancelamento num único `UPDATE` condicional.
- Limite de 3 vídeos não terminados por usuário (conta também os que estão na fila), no link, no upload
  e nos reprocessamentos; upload recusado com HTTP 429.
- Cota de armazenamento aplicada no upload e no link do YouTube.
- Excluir conta exige a senha (o Better Auth aceitava sessão recente sem senha).
- Postgres e Whisper só em `127.0.0.1` no `docker-compose.yml`.
- `UserFacingError` sem `cause` para o navegador; cabeçalhos `X-Frame-Options`, `frame-ancestors`,
  `Referrer-Policy`, `nosniff`.
- Mensagens de falha do ffprobe e do Whisper com caminho de recuperação; logs de job com contexto.
- Transcrição para a IA com centésimos.

Verificado rodando (não só por tipos):

- Cabeçalhos de segurança presentes na resposta de `/sign-in`.
- `/api/auth/delete-user` sem senha: 400 "Digite sua senha para excluir a conta."; com senha: 200
  (conta descartável criada e apagada pelo `curl`, sem tocar na sessão do navegador).
- Cancelamento de vídeo na fila: `status = cancelled`, flag e `finished_at` gravados num único `UPDATE`.
- Retomar e tentar de novo: transação + fila; o worker reconstruído pegou o job e registrou início e fim
  com `jobId`, `videoId`, status e duração.
- Com 3 vídeos na fila, "Gerar cortes" mostra "Você já tem 3 vídeos em processamento…" e nada é criado.
- Os vídeos de teste foram apagados depois.

Lacunas conhecidas desta rodada:

- Limite e cota são checados antes do insert: duas requisições simultâneas podem passar juntas
  (limite "macio"). Fechar com um `INSERT … SELECT` condicional ou advisory lock por usuário.
- `markVideoDone` e `markVideoFailed` ainda podem sobrescrever um cancelamento que chegue no último
  instante; aplicar o mesmo `WHERE` de status.

Interface:

- Autosave do Studio serializado; tempo de legenda comparado em centésimos com tolerância.
- Datas no fuso de São Paulo; formatadores de número criados uma vez.
- Hierarquia: uma ação primária por tela (sidebar secundária na página do vídeo e no Studio), seleção em
  branco sobre escuro (não verde), nota do corte menor que o título da página, níveis de título sem
  buracos, cards com a mesma superfície em todas as telas, títulos de seção iguais, 32 px entre seções
  no Painel, botão de excluir conta discreto até a confirmação.

## 8. Segunda rodada: pendências fechadas

Concorrência e banco (migração `0009_storage_bytes_and_timestamptz`):

- Limite e cota sem corrida: checagem e insert na mesma transação, com `pg_advisory_xact_lock` por usuário.
  Testado com 6 envios simultâneos: 3 passaram, 3 recusados, 3 linhas criadas.
- Máquina de estados (`ALLOWED_PREVIOUS_STATUSES`) no `WHERE` de todo `UPDATE` de status; `markVideoDone`
  e `markVideoFailed` não sobrescrevem mais um cancelamento.
- Vídeo e job da fila na mesma transação (`fromDrizzle` do pg-boss): rollback não deixa job órfão.
- `recordStop` tenta 3 vezes e registra cada falha.
- Worker: `WORKER_CONCURRENCY` (padrão 2), `groupConcurrency: 1` por usuário, `heartbeatSeconds: 60`,
  `pg_try_advisory_lock` por vídeo; `releaseOrphanedJobs` removido.
- `UNIQUE(clips.video_id, position)`; `videos.source_bytes` e `clips.output_bytes` gravados e usados pela
  tela de uso e pela cota (fim da varredura de disco por request); todas as colunas em `timestamptz`.

Segurança:

- Rate limit do Better Auth sempre ligado, com regras por rota (login 5/min, cadastro 5/h, senha e
  exclusão 5/15 min) e IP real lido do socket ou de um cabeçalho de proxy configurável
  (`TRUSTED_PROXY_IP_HEADER`). Testado: 429 depois de 5 senhas erradas, inclusive com IP forjado.
- Turnstile no cadastro e no login, ligado só quando `TURNSTILE_SITE_KEY`/`TURNSTILE_SECRET_KEY` existem.
- CSP completa com nonce por request; `BETTER_AUTH_URL` obrigatório e https em produção.
- ffmpeg e ffprobe com `-protocol_whitelist file`.
- Rotas `api/*` com wrapper de erro; `http-response.ts` e `fs-errors.ts` no lugar das cópias;
  `findTranscriptWords` único em `transcription`.

Interface e desempenho:

- Linhas da transcrição memoizadas e linha ativa por busca binária; `findCueAt` binário; arraste sem
  medir o DOM a cada movimento.
- Studio busca a transcrição uma vez por vídeo; cada troca de corte busca só um resumo leve.
- Polling só dos vídeos em andamento; a lista inteira só é recarregada quando um termina.
- Palavras de legenda exigidas em ordem no schema; evento ASS de duração zero descartado.
- `studio-workspace.tsx`, `original-player.tsx` e `cue-track.tsx` divididos abaixo do limite.

Arquitetura:

- `videos` dividido: `studio` (editor), `video-records` (a linha do vídeo e suas transições de status),
  `shell` (layout do app); download foi para `processing`, sharing e limites de corte para `clips`.
- Dependências entre módulos em mão única, verificadas por `scripts/check-module-boundaries.ts` dentro do
  `npm run check`. Única exceção documentada: `auth.server.ts` → `delete-user-videos.server.ts` (hook do
  Better Auth fixado na criação da instância).

Testes: `node:test` pelo `tsx` (sem dependência nova), 118 testes em 13 arquivos, dentro do `check`, do
pre-commit e do CI. Acharam um bug real, corrigido: pausa de exatamente 0,60 s quebrava a legenda por erro
de float (`caption-cues.ts`).

Fica para decisão:

- Verificação de e-mail (exige um provedor de envio e muda o cadastro de quem já existe).
- Paginação da lista no servidor (busca, filtro e contadores hoje rodam no navegador).
- Object storage e Whisper em GPU, quando houver um segundo host.
- Turnstile testado só sem chaves: falta rodar com as chaves reais do Cloudflare.
